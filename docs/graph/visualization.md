# Local graph visualization

`vogoban graph [path]` opens an interactive local architecture graph from the current repository's `.vogoban/graph.db`. The server binds only to `127.0.0.1`, answers only requests whose `Host` is `127.0.0.1`, `localhost` or `[::1]` (other hosts get 403, which blocks DNS-rebinding pages), and sends a strict Content-Security-Policy (`default-src 'self'`, no inline scripts, `frame-ancestors 'none'`) with `nosniff`, `X-Frame-Options: DENY` and `Referrer-Policy: no-referrer`; no account, telemetry, source upload, or hosted service is required. The client is bundled locally with React Flow, so node dragging, pan/zoom, minimap and keyboard-friendly graph controls stay in the repository-local workflow.

The Architecture, Dependencies, Infrastructure, Messaging, and Frontend views are projections of the same RepositoryGraph queried by the CLI and MCP. Search, filters, node details, relationships, provenance, bounded neighborhood expansion, and impact use actual stored graph facts. The default view intentionally favors architectural entities rather than rendering every class or method.

The workspace uses a dark, restrained visual system with a repository sidebar, type filters, and a collapsible inspector. The **Detail** selector offers **Auto**, **Overview**, and **Details**. Auto shows compact, technology-icon circles below 72% zoom and detailed cards at or above 72%. Overview keeps circles at every zoom; Details keeps cards. Circle size reflects the number of relationships in the current view, not risk or importance. Circle labels appear from 48% zoom, or when hovered, selected, or keyboard-focused; the inspector remains available at any zoom.

React Flow supplies graph interaction; Dagre positions small connected components from stored edge direction. Auto and Overview use compact force layouts for components with more than 12 entities and pack disconnected components into rows. Explicit Details uses directional card layouts, with force layout above 160 entities. Zooming in Auto changes the rendering, not node positions; explicitly changing to or from Details refits the layout. Layout changes positions only; it never adds relationships. Unconnected entities remain visible without adding inferred edges.

Overview uses Canvas for more than 500 visible relationships; smaller overviews and Details use SVG edges. Canvas draws every relationship whose endpoints are in the visible graph, without sampling, and supports clicking connections to inspect their actual source, target, evidence, and provenance. At very low zoom, Canvas keeps node rings visible and makes nearby nodes easier to select. Nonselected arrowheads are hidden below 20% zoom to reduce clutter; selection or the inspector still exposes direction. Pan, zoom, node dragging and resizing update the drawing. Canvas itself is not a screen-reader relationship list: use **Edges** for keyboard-accessible relationship inspection.

Choose **Show all relationships** to load every relationship stored for the repository and its actual endpoint entities, including source-level types, methods and files. There is no 5,000-row query cutoff. The coverage strip reports the stored relationship count, what was loaded, and any missing endpoint IDs. Missing endpoints are diagnostics, not fabricated nodes. Type filters explicitly reduce what is visible; clear them to restore all loaded entities and relationships. **Use Architecture projection** returns to progressive architectural exploration. MetaGraph stays a separate graph and has its own complete mode and endpoint inspection.

To populate MetaGraph, [register and analyze each repository into one explicit shared store, then run `metagraph build`](metagraph-workflow.md). Pass that same `--db` to `graph` and choose **MetaGraph** in the viewer. Complete mode means complete coverage of stored relationships, not complete knowledge of the system: package membership and API exposure do not establish service-to-service calls. The linked workflow records the enterprise sample's extracted contract/resource links and its remaining unresolved identities.

Search favors architectural entities before lower-level source files. Select a result or a node to inspect inbound and outbound relationships. **Focus** narrows the canvas to its direct neighborhood; **Expand** adds neighbors to the current view without a silent 120-entity display cap. **Reset view** returns to the original projection or complete graph, depending on the selected mode. Edge labels can be enabled globally; the selected relationship is always labeled, and Details also labels relationships touching the selected node. Parallel and reciprocal relationships have separate curved paths, and self-relationships have visible loops. Relationship strokes adapt to zoom so connections remain visible when fitting a large graph. Selecting an entity does not fade unrelated edges.

The inspector exposes source filenames, line numbers, analyzers, evidence levels, confidence, and deterministic impact results. Its overview's “most connected” entries count only relationships in the current view, not repository-wide centrality or a risk score.

Recognizable Azure service, Terraform, Helm, Kubernetes and Docker SVG icons appear consistently in nodes, search results, the entity list and the inspector. Azure service identity comes from stored service/ARM metadata, not resource-name guesses. A Terraform-declared Service Bus resource keeps its Service Bus icon and shows a separate Terraform declaration badge; Helm-rendered workloads similarly keep their Kubernetes identity. Unknown technologies retain generic icons. Product labels and accessible image text accompany the marks, which are bundled locally with attribution in `src/local/web/icons/NOTICE.md`; no icon CDN is needed.

Switch to **List** for keyboard-accessible textual exploration or **Edges** to inspect relationships with their actual source and target names, evidence and provenance. The Edges list uses 100-row pages; pagination does not limit the underlying graph. On smaller screens, navigation becomes an explicit drawer and entity details use a bottom panel. Focus indicators and reduced-motion preferences are respected. All client assets and icons are served locally; the UI does not fetch fonts or other assets from external services.

The overview has been browser-checked with 1,433 stored entities and 2,945 relationships, including complete Canvas edge counts, connection picking, and automatic detail switching without rearranging nodes. This is not an unlimited-scale guarantee: graph loading and layout still run on the client, and React Flow still manages the nodes. A dense complete graph can remain visually crowded; use architectural projections, explicit filters, or Focus for readable inspection. No automatic clustering or fabricated service-level links are introduced.
